# claude.ai クラウドルーチン用プロンプト（貼り付け用）

claude.ai側のデイリーキャプチャルーチンのプロンプト原本。ルーチンの挙動を変えたいときはこのファイルを更新し、claude.aiのルーチン編集画面に貼り直す。

改訂履歴:
- 2026-07-18: メール配信がカテゴリ制（AI/Hardware（半導体）/Climate & Energy/Healthcare、量子は週次分離）に移行したため、批評コメントの見出しをソース名からカテゴリ名に変更する指示に書き換え。量子ソース軽量化ルール（1日最大2記事・Key Claim中心3行以内）を追加。**この新プロンプトをユーザーがclaude.aiルーチン編集画面に貼り替えるまでは旧プロンプト（ソース名見出し）が動き続けるが、`build_digest.py` 側はカテゴリ名見出しが見つからなければGeminiフォールバックで批評コメントを自動生成する設計のため、配信自体は貼り替え前でも正常に継続する（劣化運転＝Claude批評ではなくGemini批評になるだけ）**
- 2026-07-14(2): **mainへの直接push必須**を明記（クラウド実行環境が既定でclaude/…作業ブランチにpushし、7/5〜7/13の全ソースキャプチャ9日分がmainに届かず配信されない事故が判明したため）
- 2026-07-14: 軽量化ルール追加（サブエージェント起動禁止・URL重複チェック）。ソースごとにresearchエージェント8体を起動して利用上限に達し、実行が失敗する日が多発したため
- 2026-07-13: ソースの固定列挙を削除（列挙がCLAUDE.mdテーブルより優先されてしまい、自動追加されたThe Quantum Insider（tqi-）が1週間キャプチャされない事故が起きたため。**ソース一覧は二度とプロンプトに書かない**）
- 2026-07-06: 初版（全ソース+批評コメント対応）

---

デイリーキャプチャループを実行してください。

対象リポジトリ: https://github.com/Shuhei-Tsunoda02006242/my-skill-graph-inbox （mainブランチ）

手順:
1. リポジトリを取得し、CLAUDE.md を読んで最新のキャプチャ対象ソースとルールを確認する
2. CLAUDE.md のソーステーブルに記載された**全ソース**から、本日の注目記事を最大3件ずつ取得する。ソース一覧はこのプロンプトには書かれていない——**CLAUDE.mdのテーブルが唯一の正**であり、テーブルに行があるソースは自動追加された新顔（例: `tqi-` The Quantum Insider）も含めて必ず対象にする。取得前にテーブルの行数とprefix一覧を確認して作業ログに残すこと
3. CLAUDE.md のフォーマット（frontmatter + 本文）に従い、日本語で `00-Inbox/YYYY-MM-DD-{prefix}-{slug}.md` を作成する
4. 批評コメント作成: 本日キャプチャした全記事を**配信カテゴリ別**にまとめ、`digests/YYYY-MM-DD-commentary.md` を作成する
   - カテゴリの振り分けはCLAUDE.mdの「配信カテゴリ（Sequoia風アレンジ）」表に従う（landscape-position第1セグメント優先、空欄ならソースprefixでフォールバック）
   - カテゴリごとに「## {カテゴリ表示名}」見出し + 批評本文3〜5文。見出しは次の4つのみ使う: `## AI` / `## Hardware（半導体）` / `## Climate & Energy` / `## Healthcare`（Frontier（量子）は週次ダイジェスト側でGeminiが自動生成するため、この commentary.md には書かなくてよい）
   - 観点: (1) 誇張・ハイプの可能性 (2) 記事に欠けている文脈 (3) 投資家として注意すべき点 (4) 記事間に共通するトレンド
   - このファイルは毎朝8:00 JSTのカテゴリ別ダイジェストメールにそのまま掲載される（見出しがカテゴリ名と一致しない場合はGeminiが自動生成した批評コメントにフォールバックする）
5. git commit & push
   - **必ず `main` ブランチに直接コミットし、`git push origin main` する。** `claude/...` 等の作業ブランチを作らない・ブランチにpushしない・PRを作らない。メール配信ワークフローはmainしか見ないため、ブランチにpushした成果物は誰にも届かず消える（実際に7/5〜7/13の9日分がブランチに置き去りになる事故が起きた）
   - 最後に `git log origin/main -1` で自分のコミットがorigin/mainに載ったことを確認し、載っていなければマージ/再pushしてでもmainに反映させてから終了する
   - ソースごとに1コミット: `daily: {Source} capture {YYYY-MM-DD} ({N} articles)`
   - 批評コメントは別コミット: `daily: digest commentary {YYYY-MM-DD}`
   - Author: `Claude <noreply@anthropic.com>`

ルール:
- **サブエージェント（researchエージェント等）を起動しない。** すべてこの会話の中で1ソースずつ順番に処理する（並列エージェントは使用量上限に達して実行ごと失敗する）
- **量子ソース（`qcr-`・`tqi-`）は軽量化する**: 両ソース合わせて**1日最大2記事まで**、本文は**Key Claim中心に3行以内**で簡潔に書く（Evidence / Contextを深掘りしない）。Frontier（量子）は日次配信から外れ土曜の週次サマリーに集約されるため、個別記事の詳細さより全体感の把握を優先する（使用量削減も兼ねる）
- signal-strength が moderate 以上になりそうな記事を優先する
- 過去7日以内に類似トピックをキャプチャ済みならスキップ。判定はタイトルの印象ではなく、**記事URLで00-Inbox内の既存ノートの `source:` を検索し、一致したら必ずスキップ**（同一案件の二重・三重キャプチャが実際に起きている）
- 該当記事が無いソースはスキップしてよい（no-updatesファイルは作らない）
- 必ず git push まで完了させること（途中で止めない）
- 新規ソース追加候補を見つけた場合は CLAUDE.md のソーステーブルを更新する
